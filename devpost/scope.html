Personal AI That Remembers (working title)

A personal AI chat that actually remembers — one unified memory across all sessions, so a new conversation never starts from a clean slate.

status: approved single local user RAG + hosted model — no training local demo · deployment optional 2–4 h active work

How it hangs together

The Unique Kernel

Memory with judgment. The AI reliably carries context across sessions and knows when a memory applies versus when it should be disregarded — seamless by default, with visible receipts ("pulling from your Oct 2 session…") when proof matters. Today's chatbots forget nearly 100% of conversations; a new chat is a clean slate, and users have to keep saying "remember we discussed this." This one doesn't.

Who It's For

The learner themself, first: someone who juggles seven chatbots daily (Claude, Gemini, ChatGPT, Grok, Kimi, Qwen, DeepSeek), works on thought-oriented ideas over weeks and months, and is tired of re-explaining context and getting "I have no memory of such a discussion." Built for one local user; useful to others is a later ambition, not a v1 requirement.

The Core Loop

Open the app — even a brand-new session — and say "let's continue." The AI picks up the thread:

"yesterday we looked at X, today we move on to Y."

No hunting through session history. As the conversation touches older ground, past sessions resurface on their own via keyword-based recall, all from one unified memory. They come back because context accumulates instead of evaporating.

Inspiration & Identity

The daily chatbots you use and their memory failures; the target feeling is relief — no juggling apps, no pasting chatbot A's answer into chatbot B just to grasp one concept. Voice: a thinking companion, not a flatterer — original, thought-oriented responses rather than "a pat on the shoulder or an unwarranted critique" (that tone lands fully in the later critique mode).

Why This Matters to You

In your words: current bots are "stateless," memory is "short-lived or flawed"; "I constantly have to tell them remember we discussed this." Memory is the building block; killing the app-juggling is a perk. The payoff you picture when using it: relief.

What "Working" Looks Like

On screen, in under a minute of demo: open a fresh session, type "let's continue," and the AI summarizes where the last session left off and proposes the next step — unprompted. Then the conversation brushes an older topic and the AI correctly resurfaces it (showing its source in visible mode). The "oh, that's cool" beat is the clean-slate session that isn't actually clean.

Now · Later · Cut

Now — in v1 4
  • Single-user chat app — one local user, no accounts
  • Unified cross-session memory — a first-class citizen: session (short-term) memory auto-promotes into long-term memory, uniquely persistent and scalable; long-term memory lives in a database, indexed for faster fetching. RAG over stored sessions; hosted API model, no training
  • "Let's continue" continuity — new sessions pick up where the last left off
  • Keyword-based recall — older sessions resurface when the conversation touches them; memory runs invisible (seamless) and visible (shows what it recalled, from where)
Later — worth doing 4
  • Critique / second-opinion mode — original, thought-oriented pushback; replaces carrying chatbot A's answer to chatbot B. Builds on memory, so it comes after
  • Memory dashboard — view, edit, delete what the AI remembers
  • Deeper long-term profile — goals and ongoing projects tracked over months
  • Fine-tuned local model — served with Microsoft Foundry Local
Cut — with reasons 4
  • Fine-tuning / model training — v1 proves the idea with RAG + a deployed model
  • Multi-user accounts & onboarding — one local user proves the kernel
  • Mobile app & voice — the kernel is memory, not modality
  • Deployment / hosting — the hackathon targets a local demo; deployment is optional
